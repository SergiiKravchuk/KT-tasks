# Domain Docs

## Before exploring

Read root `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the work.

If these files are absent, proceed silently. Domain modeling creates them
when terminology or decisions are resolved.

## Layout

Single-context repository:

- `GLOSSARY.md`: domain terminology.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use the glossary's terms in issue titles, proposals, hypotheses, and tests.

If a needed concept is missing, reconsider whether it fits the project's
language or note the gap for domain modeling.

Explicitly identify any proposal that conflicts with an existing ADR,
including the ADR reference and reason for revisiting it.
